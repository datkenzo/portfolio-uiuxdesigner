AVIRON DESIGN SYSTEM

At Aviron, I built the company's first Design System to unify the visual language across multiple platforms. However, the fitness app stick on the exercise machine is the main project, therefore I give it first priority to improve its DS. And this is the subject of this case study.

PROBLEM STATEMENT

I joined the company and received design file without a DS or any location on Figma to store all of the components. 😱😱. As the only designer at the time, when I start a new design, I have to go back through the old stuff to see if there are any regulations or whether this button had been created. Fortunately, it followed some unwritten laws, which only the designer knew before she left. I noticed differences in UI components, spacing, colors, and font amongst items. This hampered development and had an influence on the user experience. So the DS is a must have.

GOAL

The main goal was to create a scalable, flexible, and easy-to-maintain design system that could grow with the product and team.

All necessary components for quicker design process and reusable.

Every design will be applied tokens for spacing, color, font size.

MY ROLE

I led the entire process — from auditing existing designs and defining tokens, to creating reusable components and writing documentations

SET UP THE COMPONENT LIBRARY

My approach to component design is to make base components as detailed as possible — covering edge cases, states, and variants — so designers don't need to detach them during real use. At the same time, I prioritize clarity and flexibility, ensuring components remain intuitive and easy to customize.

While this case highlights the button component, the rest of the system was built with similar principles — modular, scalable, and easy to use without detaching (Not at all 🤣)

TRANSITIONS

Motion has always been one of the areas I’m most excited about in product design. Beyond just making the interface feel smoother, well-defined transitions help communicate hierarchy, guide user attention, and strengthen the personality of the product.
In this section, I consolidated a set of transition rules for the Aviron Client App to ensure consistency across screens and interactions. These guidelines became a shared reference for designers and developers, helping the entire product feel more cohesive and intentional.

Principles

Purposeful

All animations help users reach their goals by surfacing connections between states or views, drawing attention to important details, or providing feedback.

Consistent

Consistently applying the right type of transition helps make apps feel cohesive and predictable to use.

All animations help users reach their goals by surfacing connections between states or views, drawing attention to important details, or providing feedback.

Animation Pattern

Pressing Animation (on a List)

This pattern was designed to provide users with clear feedback indications about their activity. Especially when the user hits one card or button on a list with the same levels of hierarchy to make it easy to figure out.

Button Pressing

Every button should be shown to users that they was clicked by a changing color state

Transition Pattern

Home Switch Menu Transition

When switching between the five tabs in the bottom bar, the transition should be consistent. The existing tab will slide down so that the new one can move up.

Forward and backward

This pattern is used to navigate between displays with consecutive levels of hierarchy, such as from a list menu to a game detail screen. A horizontal sliding animation moving forward or backward between screens.

GO Button Transition

Because it's the final step in starting the workout, needs a more appealing animation when the user taps it.

Enter and Exit

Using to add or delete a component from the screen. Components can enter and exit within the screen borders, such as a message box that appears over an app

Side Menu

The menu will slide from the side of the button that the user pressed and close in the opposite direction.

Pop-up with Button

Pop-up will expand and collapse in center of screen.

Prioritize, order, and group

When transitioning with many items, prioritize them to help users focus on important interactions. Instead of showing everything at once, organize them by priority.

OUTCOMES

  • Faster Design Process thanks to components and tokens library (less visual guesswork, more trust in the system)
  • Improved Consistency across screens.
  • Clear naming conventions made component usage intuitive and easy to find.
  • Less detaching of components - designers stayed within the system, easy to adjust, reducing errors or missing when update.
  • Centralized documentation helped both new and experienced designers stay aligned, easier onboarding (not like me 🥹)
  • Better collaboration we do not receive questions like "How is this button when user pressed?"
  • Scalable system ready for future products, platforms, and brand updates
  • More time for problem-solving, less time on UI polishing.
